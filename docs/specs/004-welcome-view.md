## 4. Functional Requirements

### REQ-001: 保留并校准现有欢迎界面

- User Story: 作为到店顾客，我希望绑桌后看到完整的门店与桌台欢迎信息，以便确认自己没有走错桌。
- Priority: P1
- Description: 保留 `WelcomeView` 现有结构与文案：门店图片与门店名、欢迎徽章、欢迎标题、「您在 <桌台> · <区域>」、主按钮「进入点餐」；桌台与区域文案沿用既有 `tableAreas` 映射与 i18n 资源。

Acceptance Requirements (EARS):
- REQ-001.1: 当用户在首页选择任一桌台（A08/B12/C06/D03）时，系统应进入 `#/welcome` 并展示该桌台的编号与区域名。
- REQ-001.2: 欢迎页应展示门店图片、门店名、欢迎徽章、欢迎标题、「您在 <桌台> · <区域>」与「进入点餐」主按钮。
- REQ-001.3: 当界面语言为 zh 或 en 时，系统应展示对应语言的完整欢迎文案，且页面不得出现未翻译的 i18n key 字面量（如 `welcome.title`）。
- REQ-001.4: 当用户点击「进入点餐」时，系统应进入 `#/menu` 并展示菜单页，桌台绑定保持不变。

Gherkin:

```gherkin
Scenario: 绑桌后进入欢迎页
  Given 用户位于首页且未绑定桌台
  When 用户选择 A08 桌台
  Then 地址变为 #/welcome
  And 页面展示门店名、欢迎标题
  And 页面展示 "A08 · 大厅"
  And 页面展示「进入点餐」按钮
```

### REQ-002: 欢迎页提供返回选桌入口

- User Story: 作为绑错桌台的顾客，我希望在欢迎页直接返回选桌，以便自助纠正而不必刷新页面。
- Priority: P1
- Description: 在欢迎页卡片内、主按钮下方提供「返回选桌」次要文字按钮；点击后回到 `home` 视图（`#/home`）并解除当前桌台绑定，用户可以重新选桌。

Acceptance Requirements (EARS):
- REQ-002.1: 当用户在欢迎页点击「返回选桌」时，系统应进入 `#/home` 并清空当前桌台绑定。
- REQ-002.2: 当用户返回首页后重新选择桌台（如 B12）时，系统应在欢迎页展示新桌台及其区域名，不得残留旧桌台。
- REQ-002.3: 「返回选桌」应仅重置桌台绑定，不得修改购物车、已提交订单、服务请求与支付状态。
- REQ-002.4: 返回首页后，若用户通过浏览器后退请求 `#/welcome`，因当前无桌台，系统应按既有不可达规则回落到 `#/home`，不得展示旧桌台欢迎页。
- REQ-002.5: 返回入口应具备可读的可访问名称（zh「返回选桌」/ en「Change table」），支持键盘操作，触控区域不小于 44×44 px。

Gherkin:

```gherkin
Scenario: 返回选桌并重新绑定
  Given 用户已在 A08 桌台的欢迎页
  When 用户点击「返回选桌」
  Then 地址变为 #/home
  And 首页选桌卡片可见
  When 用户选择 B12 桌台
  Then 地址变为 #/welcome
  And 页面展示 "B12 · 卡座"
  And 页面不展示 "A08"
```

### REQ-003: 欢迎页可访问语言与老人模式

- User Story: 作为老年用户或非中文用户，我希望在首屏就能调整字号与语言，以便无需先进入点餐即可舒适阅读。
- Priority: P2
- Description: 在欢迎页门店图片右上角提供轻量控制区，复用 `App.tsx` 既有的 `toggleLanguage` 与 `handleToggleElderly` 能力，不引入第二套偏好实现；控制区不遮挡欢迎标题、桌台信息与主按钮。

Acceptance Requirements (EARS):
- REQ-003.1: 当用户在欢迎页点击语言控件时，系统应在中文与英文之间切换，欢迎页全部文案随之更新。
- REQ-003.2: 当用户在欢迎页切换语言后进入点餐时，系统应保持所选语言，菜单页与顶栏文案一致。
- REQ-003.3: 当用户在欢迎页开启老人模式时，系统应放大页面字号；进入点餐后应保持开启状态，再次点击可恢复常规模式。
- REQ-003.4: 控制区应位于门店图片右上角浮层内，不遮挡门店名、营业状态、欢迎标题、桌台信息与主按钮；在 320×568 视口下各元素应完整可见且互不重叠。
- REQ-003.5: 语言与老人模式控件应具备随界面语言变化的可访问名称，触控区域不小于 44×44 px，键盘可聚焦且焦点环可见。

### REQ-004: 欢迎页独立 E2E 验收

- User Story: 作为测试/评审人员，我希望欢迎页的关键行为有自动化断言，以便回归结果可客观判定。
- Priority: P1
- Description: 新增或扩展 Playwright 用例，覆盖欢迎页核心元素、进入点餐、返回选桌、深链绑桌与偏好保持，遵循 `docs/agent-testing.md` 的执行约束。

Acceptance Requirements (EARS):
- REQ-004.1: 绑桌后，E2E 应断言欢迎页出现门店名、欢迎标题、桌台编号与「进入点餐」按钮。
- REQ-004.2: 点击「进入点餐」后，E2E 应断言地址为 `#/menu` 且菜单页可见。
- REQ-004.3: 点击「返回选桌」后，E2E 应断言地址为 `#/home` 且选桌卡片可见。
- REQ-004.4: 直接访问 `/#/welcome` 时，E2E 应断言自动绑定示例桌台 A08 并展示欢迎页。
- REQ-004.5: 欢迎页切换语言与老人模式后，E2E 应断言进入点餐仍保持所选语言与老人模式。
- REQ-004.6: `npx playwright test` 应全量通过；核心元素用例应同时覆盖 zh 与 en 两种语言。

## 5. UX Design

### 5.1 体验目标与原则

- **不打断**：欢迎页仍是单屏确认页，新增入口只做「纠错」和「可读性」，不引入弹窗、二次确认或新流程。
- **主次分明**：「进入点餐」保持唯一主操作与整行宽度；「返回选桌」为弱化文字按钮；偏好控件为图标/短文案浮层。
- **视觉最小改动**：沿用现有卡片、配色、图片与间距，不新增页头、不改卡片骨架。

### 5.2 页面结构与控件位置

自上而下保持现有结构，仅新增两处：

1. **图片区右上角浮层**：语言控件（可见文案 `EN` / `中`）与老人模式控件（`Accessibility` 图标，开启态高亮，与 `TopBar` 一致）。两控件并排、44×44、白色高不透明度底、`charcoal-900` 前景。
2. **主按钮下方**：「返回选桌」文字按钮，居中、弱化样式（ghost/无边框）、44px 高，与主按钮保持至少 8px 间距；不与主按钮同权重。

### 5.3 交互与状态

| 交互 | 反馈 | 约束 |
|------|------|------|
| 点击「返回选桌」 | 立即进入 `#/home`，选桌卡片出现 | 无二次确认；不触发下单 |
| 点击语言控件 | 文案即时切换，控件可访问名称同步变化 | 选择写入既有 `i18nextLng` 持久化链路 |
| 点击老人模式控件 | 字号即时放大/恢复，图标高亮变化 | 复用既有 `elderly-mode` 持久化与 `html.elderly` |
| 点击「进入点餐」 | 立即进入 `#/menu` | 保持既有行为 |

### 5.4 文案

| i18n key | zh | en | 用途 |
|----------|----|----|------|
| `welcome.back` | 返回选桌 | Change table | 欢迎页次要按钮可见文案与可访问名称 |
| `common.aria_elderly_on` | 切换至老人模式 | Turn on elderly mode | 老人模式关闭时的控件可访问名称 |
| `common.aria_elderly_off` | 切换至常规模式 | Turn off elderly mode | 老人模式开启时的控件可访问名称 |
| `common.aria_lang`（既有） | 切换语言 | Switch language | 语言控件可访问名称；可见文案为 `EN` / `中` |

既有欢迎文案保持不变：`welcome.badge`、`welcome.title`、`welcome.you_at`、`welcome.enter`、`welcome.img_alt`。

### 5.5 响应式与可访问性

- 320px：卡片为单列，控件不得挤出卡片或覆盖标题/桌台/主按钮；允许页面纵向滚动。
- 768px / 1280px：保持现有 `max-w-md` 居中卡片，不因新增控件改变卡片宽度与对齐。
- 所有新增控件使用原生 `button` 语义与可访问名称；键盘 Tab 顺序为「语言 → 老人模式 → 进入点餐 → 返回选桌」。
- 控件前景/背景对比度满足 WCAG AA（正文 ≥ 4.5:1，非文本控件 ≥ 3:1）。

## 6. 产品规则

### 6.1 状态与流转

| 操作 | 前置状态 | 目标状态 | 用户可见反馈 |
|------|----------|----------|--------------|
| 绑定桌台 | `home`（`table = null`） | `welcome`（`table = 所选桌台`） | 欢迎页展示该桌台与区域 |
| 进入点餐 | `welcome` | `menu`（桌台保持） | 菜单页与顶栏桌台信息 |
| 返回选桌 | `welcome` | `home`（`table = null`） | 选桌卡片重新出现 |
| 深链 `#/welcome`（首次加载） | 任意（无桌台） | `welcome`（`table = A08`） | A08 欢迎页 |
| 深链 `#/welcome`（已绑桌台） | 任意（`table` 非空） | `welcome`（保持当前 `table`） | 当前桌台欢迎页 |

### 6.2 边界与异常

- 无桌台时请求 `#/menu`、`#/order`、`#/checkout`：按既有 `canView` 规则回落到 `#/home`，本次不改。
- 返回选桌后浏览器后退请求 `#/welcome`：当前无桌台，按既有规则回落到 `#/home`。
- `localStorage` 不可用：语言与老人模式降级为内存态，不报错、不阻塞，与既有实现一致。
- 快速重复点击「返回选桌」或「进入点餐」：结果幂等，不产生额外页面或错误提示。

### 6.3 字段与校验

无新增字段与校验。

### 6.4 接口或数据契约

无对外接口、数据格式或持久化结构变化；仅组件 props 与内存态视图流转调整。

## 9. 需求分级（按《需求打标规范》）

| 维度 | 结论 | 理由 |
|------|------|------|
| scope | PASS | 预计涉及 `WelcomeView.tsx`、`App.tsx`、`i18n.ts`、`e2e/view-routing.spec.ts` 或新增 1 个 spec，文件数 < 15，集中在前端视图层 |
| interface | PASS | 无 API 变更；仅组件 props 扩展与既有视图跳转复用，技术路径唯一 |
| pattern | PASS | 语言/老人模式切换、视图跳转、E2E 路由与元素断言在 `TopBar`、`App.tsx`、`view-routing.spec.ts` 均有先例 |
| testability | PASS | 元素存在性、URL、文案、字号状态、位置关系均可由 Playwright 客观断言 |
| dependency | PASS | 无新增 SDK、服务、凭据或环境 |
| safety | PASS | 纯前端展示与导航，不涉及支付、隐私、权限、数据迁移 |
| closure | PASS | 单仓库单前端模块闭环 |

**分级结论：A 类（AI 全自动编程）**，七维全部 PASS，可由 Agent 直接实现并自验，人工仅做最终 Review。判定明细见同目录 `004-welcome-view.tagging.json`。
